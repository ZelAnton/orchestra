# cc-focus: согласование контекста и защищённых файлов

## Причина остановки Orbit

P04.2 остановлен в фазе Astra. Восстановитель Astra/xhigh уже выполнил диагностику,
но runtime продолжал сравнивать актуальные инструкции с первоначальным снимком.
Расхождение затрагивает два общих файла (`AGENTS.md`, `HANDOFF.md`) и 19 защищённых
файлов в Core, Root и Specification. Новый handoff и `--retry` не принимают такие
изменения. Простое обновление только общих файлов оставило бы второй blocker.

Orbit использован только для чтения. Его исходники, Git, leases и `.work/cycle`
не изменялись; P04.2 не возобновлялся. Сохранённый healer report не засчитан как
ревью или разрешение на передачу защищённой работы.

## Изменение runtime

Добавлен модуль `tools/focus_reconcile.py`, включённый в штатный cc-sync:

- `cc-focus reconcile --plan-out .work/focus-reconcile.json` создаёт новый план;
  команда без `--plan-out` показывает предложение, ничего не принимая.
- `cc-focus reconcile --apply-plan FILE` принимает именно проверенный план.
  Запуск модели, изменение исходников, индекса или Git history не выполняются.
- Общие файлы получают актуальные read-only ожидания и остаются вне публикации.
  Перечисленные защищённые файлы передаются текущей итерации целиком, включая
  прежние незакоммиченные правки. Их база публикации — Git HEAD с checkout
  окончаниями строк/фильтрами; для новых файлов базы в Git нет. Исходный dirty
  снимок остаётся в архиве. Другие защищённые файлы и staging сохраняются.
- Исходное состояние и точный план архивируются как checksummed correction.
  Сохраняются текущая задача и сессии; незавершённый вызов заменяется новой
  correction revision. Требуются кодирование того же этапа и оба ревью заново.
- План привязан ко всему checkout, HEAD/index и смысловым полям состояния.
  Исключены только время сохранения и служебные данные leases. Изменённые или
  устаревшие планы отклоняются, включая изменение файлов во время архивирования.
- Используются обычные project/member locks, leases и проверка выхода провайдера.
  Учитываются PAUSE/stop и неопределённая доставка сообщений. Нельзя откатить
  публикацию/CI, сменить HEAD, состав репозиториев или protected staging.
- Провайдерам прямо запрещено применять планы для выдачи себе полномочий.
  Внутри одиночного Git-репозитория файл плана должен быть ignored, иначе нужен
  внешний путь. Существующие файлы не перезаписываются.

Сохранение correction вынесено в общий `Cycle.record_correction`. При ошибке
сохранения восстанавливается прежнее состояние в памяти, чтобы аварийное
сохранение статуса `interrupted` не приняло неудавшуюся передачу владения.
Пользовательские настройки, permissions и credentials не менялись.

## Проверка

- Полный `tests/launchers/run-all.ps1`: **12/12**, exit 0, **463556 ms**,
  survivors **0**; 18 Windows-only наборов пропущены на Linux.
- Полный прогон завершил focus-поднабор до последнего исправления обработки
  неудачной записи. После него отдельно повторён весь `test-cc-focus.ps1`:
  workflow **147** (4 skips), terminal **56**, status **17**, project **43**
  (1 skip); всё прошло. Это отдельный повтор затронутого набора, не второй полный
  launcher-прогон.
- Одноразовый проект прошёл обе команды через настоящий PowerShell launcher и
  ProcessKit. Реальные project/member leases освобождены, модели не вызывались,
  исходники и сессии сохранены.
- Проверены раздельная публикация принятых файлов в два локальных Git remote,
  сохранение постороннего staging третьего репозитория, откат последнего edit,
  возврат к HEAD, удалённый untracked-файл, CRLF, устаревший/исправленный JSON,
  конкурентная запись, stop, сбой persistence и повторное согласование.
- Python syntax, UTF-8 без BOM, whitespace изменённых строк и `git diff --check`
  прошли. Generated Claude/Codex роли не изменились. Предшествующее предупреждение
  о CRLF в `.claude/settings.local.json` не относится к этой правке.

В первом цикле саморевью второй проход выявил сохранение принятого владения в
памяти после ошибки записи. Проблема воспроизведена и исправлена; отсчёт начат
заново. После исправления проведены **три последовательных чистых прохода
саморевью Codex**, без делегирования, над одним неизменным снимком 11 файлов.

Артефакты: `.work/focus-reconcile-review-snapshot.json`,
`.work/focus-reconcile-review-pass{1,2,3}.json`, сохранённые `review-initial-*`,
`.work/focus-reconcile-suite.log`, `suite-summary.json`, `final-focus.log` и
`wrapper-smoke.log` с тем же префиксом `focus-reconcile-`.

## Установка и Orbit

Установлено штатным `cc-sync` от anton. Пять изменённых Python runtime-файлов в
mirror побайтно совпадают с проверенным исходником. Пять проверяемых файлов
настроек не изменились; снимок ревью после sync также совпал.

Точный план текущего Orbit сохранён вне Orbit:
`/srv/dev/projects/orchestra/.work/orbit-focus-reconcile.json`.
План сверён установленным runtime от имени anton без изменения состояния проекта:
2 действия `refresh-context`, 19 действий `adopt-file`.

После проверки содержимого перечисленных файлов оператор может выйти из старого
припаркованного интерфейса через `/exit` и выполнить:

```sh
cd /srv/dev/projects/Orbit
cc-focus reconcile --apply-plan /srv/dev/projects/orchestra/.work/orbit-focus-reconcile.json
cc-focus
```

Это вернёт P04.2 в кодирование и обязательные ревью. Если Orbit изменится до
применения, команда потребует новый план. Самостоятельное применение к Orbit в
этой работе не выполнялось: граница `AGENTS.md` разрешает читать другие проекты,
но запрещает менять их `.work/` в задаче Orchestra.
