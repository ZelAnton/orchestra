# cc-focus: согласование до начала кодирования

Дата: 2026-09-14.

Interlink остановился на `protected-work` в новой итерации после публикации V10:
`phase=code`, `code_started=false`. Согласование предлагалось как выход, но его
проверка допускала только уже начатый этап. Orbit остановился на существующей
границе `project-context-changed` во время ревью P04.2.

## Исправление

- `reconcile` допускает ещё не начатую итерацию code. Применение сохраняет
  `code_started=false`, сессии, HEAD, файлы и staging; предварительная метка задачи
  очищается. Следующий этап выбирается из актуального плана, не из старого отчёта
  о публикации. Начатый этап продолжает прежний маршрут восстановления.
- Correction фиксирует `before_code`; новый вызов кодирования не описывается как
  восстановление потерянного отчёта. Для ранее начатых/прерванных вызовов маршрут
  восстановления сохранён.
- Переданные защищённые файлы по-прежнему требуют кодирования и обоих ревью до
  публикации. Обновление только read-only контекста при исчерпанном плане и без
  неопубликованных изменений не требует придумывать новую стадию.
- `protected-work` объясняет необходимость явного согласования и то, что
  `--retry` сам по себе не передаёт права на файлы. Автоматическое принятие планов
  восстановителем не добавлялось.

При проверке предыдущего GitHub CI обнаружены ошибки Windows-фикстур: короткие
TEMP-пути сравнивались с каноническими, UTF-8 читался через системную code page,
а тест пытался прочитать байт через второй handle под обязательной блокировкой.
Фикстуры используют канонические пути и UTF-8 профиль штатного launcher. Проверка
lock проверяет metadata под блокировкой, содержимое — после освобождения.
Проверки профиля провайдера и runtime-блокировки не ослаблены.

## Проверки и ревью

- Полный launcher/runtime набор: 12/12 terminal green, survivors=0. На Linux
  пропущены 18 Windows-only наборов.
- После последних правок отдельно повторён весь focus-набор: 152 workflow,
  56 terminal, 17 status, 44 project; всего 269 тестов, из них 5 пропущены.
- Проверки охватывают применение до начала code через CLI без модели, сохранение
  файлов/сессий, обязательные оба ревью перед push, запрет преждевременного
  завершения с переданными изменениями и завершение исчерпанного context-only плана.
- Consistency, Python syntax, гигиена diff и отсутствие дрейфа генерируемых ролей
  проверены. Установленные runtime-модули побайтово совпадают с исходниками.
- После исправлений выполнены два последовательных чистых прохода Codex
  self-review. Другой агент не привлекался; независимое ревью не заявляется.
- Новое прохождение Windows подтверждается отдельно GitHub CI; Linux-проверки
  не засчитываются как Windows-прогон.

Подготовлены и проверены установленным runtime планы для Interlink (4 защищённых
файла) и Orbit (2 общих файла контекста и 19 защищённых файлов репозиториев).
Планы и reviewable содержимое/диффы сохранены только в `.work` Orchestra.
Снимки исходников, HEAD/index и сохранённое состояние обоих проектов не менялись.
Применение планов и возобновление циклов этим изменением не выполнялись.
