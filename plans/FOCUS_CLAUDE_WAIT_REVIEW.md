# cc-focus: ожидание длинных команд Claude

## Исправление

В Interlink вызов `17f75b3201924c4590baeb9229baa772` получил `result` с текстом
ожидания Monitor при незавершённых native tasks. Runtime закрыл stdin и через
30 секунд остановил контейнер провайдера. В сохранённом протоколе после этого
`result` есть успешное завершение команды Integration и продолжение работы Claude.
Это не завершённый проход ревью; его зачёт не восстанавливался.

`cycle_transport.py` задаёт для дочернего Claude и inline settings
`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, Bash timeout по умолчанию 30 минут и
максимум шесть часов. Monitor, CronCreate, ScheduleWakeup, RemoteTrigger и Workflow
добавлены к запрещённым инструментам последовательного профиля. Общий лимит
вызова остаётся шестичасовым. Модель, effort, permission mode и session ID не меняются.
Основание для настройки: [официальные переменные Claude](https://code.claude.com/docs/en/env-vars).

Для native continuation из прежних сессий runtime учитывает `task_started`,
`task_notification` и `queued_turn_count`. Промежуточные ответы сохраняются в
`deferred-*.txt`, не закрывают интерактивный stdin, не отправляют очередное указание
оператора и не засчитывают ревью. Нужен последующий итоговый отчёт. Если промежуточный
структурированный отчёт уже указывает исправления, их количества и substantial
сохраняются как нижняя граница при объединении с окончательным отчётом. После этого
действует прежнее суммирование отдельных ответов на сообщения оператора.

EOF без итогового отчёта остаётся ошибкой. Остановка оператора и очистка дерева
процессов сохраняются. Grace в 30 секунд начинается только после последнего ответа.
Панель сообщает о полученном ответе, не объявляя процесс завершённым по одному событию.
Контракт профиля и документация обновлены.

## Orbit: отдельная причина остановки

Проверка исходников была только read-only. `Specification/Requirements/DATA_MODEL.md`
требует local human assurance для `direct_human`. `Root/deploy/pg_hba.conf` допускает
локальный peer только для postgres, прочие local connections отклоняет; сетевые
соединения с Orbit используют сертификаты. `Core/schema/README.md` прямо отмечает,
что текущая battery не подтверждает human ceremony и имеет `acceptanceComplete=false`.

`Root/AGENTS.md` требует: «Изменение действующего артефакта требует отдельной
согласованной задачи». Снимок текущего цикла также защищает предшествующие изменения
Root и Specification. Поддержка нескольких репозиториев не снимает этих требований.
Нужна отдельная задача на доверенный канал подтверждения человека и проверяемый
сервером контракт, с согласованием владения существующими изменениями. Изменять
защищённые файлы или считать клиентский хеш доказательством присутствия этот фикс
не разрешает. Повторный запуск сам по себе этот blocker не устраняет.
